# video-notes

把一部长视频变成可按主题阅读、可跳转到原片时间点的文字笔记。本地运行的工具：识别、说话人分离在本地跑，主题分析与笔记只经过你配置的一个 OpenAI 兼容端点。

## 流水线

`vnote extract <视频>` 一次跑完三步，串行执行：

1. 转写。音频按语音停顿切成 10–15 分钟的块，逐块转写后拼成一条连续时间轴，块内长句不切分；说话人分离按块处理，声纹在全部块结束后一次全局聚类，同一人在整条视频里是同一个编号。识别用 FireRedASR v2 CTC（sherpa-onnx int8 模型，纯 bun 运行，不带 Python），支持到 2 小时的视频。
2. 主题分析。字幕先按纠错词表做字面替换，再逐块送 OpenAI 兼容端点产出候选主题，全部分块完成后跑一次全局合并，把跨块属于同一主题的候选并成一个带多个时间段的主题，同时给出标题和摘要。
3. 生成笔记。按选定主题产出每主题的 `topic.md` 与该主题的切片 mp4，并写 `index.md` 主题目录。

## 产物

每个视频一个输出目录（首次生成时确定 id 与目录，之后不再变）：

| 文件 | 内容 |
|---|---|
| `index.md` | 本视频的主题目录，链接各主题的 `topic.md` |
| `<主题>/topic.md` | 该主题的笔记：标题、摘要、要点，按说话人组织的正文；每个时间段标注起止时间并链接该时间段的切片 |
| `<主题>/*.mp4` | 按时间段切出的切片。切片起点比时间段起点前移 3 秒，前移后相互重叠的时间段合成一个切片，所以切片与时间段不是一一对应 |

notes 根目录另有 `index.json`，记录 id ↔ 输出目录 ↔ 显示标题。给视频改名只改显示标题，不动目录，已发给别人的路径不会失效。`index.md`（每个视频一份，主题目录）与 `index.json`（notes 根目录一份，id 映射）是两份不同的文件。

## 纠错词表

JSON 格式，一份全局 + 每视频一份，按字面替换，不做模糊匹配；同一原文冲突时视频专属词条优先。词条格式是「识别错误原文 → 正确写法」，大小写、空格、标点与原文不符就不会命中。识别引擎没有热词接口，纠错词表是修正专有词（尤其英文术语）的唯一手段；替换发生在转写之后、主题分析之前，词表也会随生成笔记的请求作为正确写法提示传给模型。

## 缓存

每一步的产物按输入内容的哈希落盘：分块转写、纠错后的字幕、每块的候选主题、每主题的笔记与切片。失效范围由真实输入决定：

- 改纠错词表：只重做字面替换与受影响主题的笔记，不重转写。
- 改端点或模型：候选主题与笔记重做，转写与替换保留。
- 某个分块转写失败：只重跑该块。
- 改一个主题：只重生成该主题的笔记与切片，其余主题沿用缓存；合并或拆分后新主题的笔记与切片重算，被并入的旧主题记录删除。

自动检测出的主题可以改名、合并、拆分、调整时间段，并选择哪些主题生成笔记。编辑作为持久记录独立保存，不写进缓存，重算不会覆盖编辑。

## 平台与模型

首发 macOS Apple Silicon。首次启动下载识别、说话人分离与标点模型，下载支持断点续传，落盘后校验 sha256；也允许手动放入模型目录，供离线或受限网络使用（手动导入同样过 sha256 校验）。Windows 暂不验证、不承诺可用。

## 命令与开发

开发期用 `bun run vnote extract <视频> [--out <目录>]`，或 `bun link` 之后直接用 `vnote`。`--out` 指定该视频的产物输出目录。

```bash
bun run typecheck
bun test
```
