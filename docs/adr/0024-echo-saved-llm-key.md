# 设置页回显已保存的 LLM API key

[ADR-0023](./0023-llm-provider-config-form.md) 第 3 条把「key 永不上行回显」写成硬规则：IPC 返回值不含 key，表单里空的 `apiKey` 表示「保留已存 key」。落地后用户在设置页看不到自己保存的 key：输入框在保存成功后清空，提示只写「已保存 key；这里留空继续使用，输入则覆盖」。用户无法确认到底存进去了什么，替换时也只能盲粘；模型名组合框还因为「按当前值过滤候选」，选中一个模型后再次展开只剩它自己。本 ADR 只改这两处界面语义，三字段单一来源、打包版不读 `.env`、一次凭据事务都不变。

## Status

已接受（accepted）。取代 [ADR-0023](./0023-llm-provider-config-form.md) 第 3 条里「key 永不上行回显」与「表单里空的 `apiKey` 表示保留已存 key」的后半句（空值仍表示保留，但不再是唯一选择）；[ADR-0015](./0015-prototype-deferred-features.md) 里「永远不回显已存 key」只保留给远程 ASR。

## 决定

1. **LLM key 回显。** `LlmStatus.apiKey` 带生效中的 key 明文（密钥库里的已存值，dev 模式下没有已存值时是 `.env` 种子），没有 key 时为 `null`。设置页打开时把它回填进密码输入框：掩码显示，点眼睛图标看明文，直接编辑输入框就是替换。保存成功后输入框保留新值，不再清空。
2. **「空 key = 保留」仍然成立。** 输入框被清空时 `llmPatch` 不发送 `apiKey`，主进程按既有语义保留已存 key；`llmDirty` 也不把「空」算成改动。key 比较统一走 trim 后的值，回填值与已存值相同时「保存」保持禁用。
3. **安全边界只剩一处让步。** key 会经 IPC 回程到渲染进程并留在输入框的 DOM 值里，因此不再承诺「日志、错误文案、IPC 返回值都不含 key」中的 IPC 部分；日志与错误文案的脱敏规则不变。远程 ASR 的 key 保持不回显。用户明确表示 key 安全不是优先项。
4. **模型下拉始终是全集。** 组合框的候选列表只在「用户正在输入」时过滤；展开、聚焦、点输入框、点箭头都以全部已拉取模型开始，并且当前选中项在列表里标为选中。关闭列表后再点输入框能重新展开（焦点还在输入框里时不会再触发 focus）。
5. **文档与验证同步。** GLOSSARY 的「LLM 提供方配置」「密钥库」条目、`verify-video-notes` 技能的设置页 handles 与「LLM 保存闭环」配方都要按新语义改写：保存后 key 输入框非空、眼睛切换出明文、再次展开下拉是全集。

## Considered Options

- **保持不回显，只把提示写清楚**：用户仍然无法核对保存结果，替换只能盲粘；这次报告的问题仍会在下一次出现。不采用。
- **回显掩码占位符（如 `••••••••`）而不是真值**：看着像有 key，眼睛也看不到内容，等于假回显；用户要的是「看到自己存的东西」。不采用。
- **单独加一个「查看已保存 key」按钮**：多一步、多一处状态，回显与编辑仍然分裂；直接回填输入框是同一个目的的最短路径。不采用。
- **模型字段改成纯 `<select>`**：列表里没有的模型名就输不进去了。保留组合框，只把过滤时机收窄到「正在输入」。不采用。

## 后果

- IPC 契约变化：`LlmStatus` 新增 `apiKey: string | null`；其余字段不变。
- 渲染进程：`draftFrom` 从 `LlmStatus` 回填 key，`llmDirty` / `llmPatch` 用「已存 key」作基线；保存成功后按服务端返回值回填（保存期间用户又改过则保留草稿）。
- 组合框：`modelOptions(fetched)` 不再接收「当前输入」，只做去重；过滤状态归组合框内部，展开即清零。
- 打包版与 dev 的差异仍在：打包版 key 只来自密钥库；dev 模式下没有已存 key 时回填的是 `.env` 种子，提示文案为「当前 key 来自 dev 模式 .env 种子；保存后以这里为准」。
