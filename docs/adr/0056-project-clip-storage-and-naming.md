# 项目切片统一放在 `<项目目录>/clips/<序号>-<标题>.mp4`

现有切片跟着视频走：每个主题一个文件，写在 `<视频输出目录>/<主题目录>/topic.mp4`，文件名固定，主题标题只体现在目录名（[ADR-0026](./0026-single-file-topic-clip.md)）。整理切片要按**项目**集中管理产出：用户点一次「打开切片目录」就该看到这次直播拆出的全部切片，而且同一项目里多个来源视频的切片要能按生成顺序排在一起。主题标题是自由文本，原型允许「为什么你的选题没人看？」这类带标点的标题，直接把标题拼进文件名会在 Windows 上失败。本决定把切片从视频目录搬到项目目录，并定死命名与清洗规则。

## Status

已接受（accepted，2026-11-06，r77）。只改切片文件的**位置与文件名**；切片怎么规划和切割仍归 [ADR-0026](./0026-single-file-topic-clip.md)（`planTopicClip`、逐段重编码、段偏移表、每主题单文件），存储仍是本地文件 + JSON（[ADR-0002](./0002-filesystem-and-json-storage.md)）。「每段切片前是否多留 2 秒」在本 ADR 中留作 Open Question，见文末。

## 决定

1. **位置。** 项目切片一律写到 `<项目目录>/clips/`，目录在第一次产出切片时创建；不再写进视频自己的主题目录。非项目切片（「整理笔记」页原有的 `topic.mp4`）路径不变，两套产出可以并存。
2. **文件名。** `<三位序号>-<清洗后的主题标题>.mp4`。序号与标题之间用半角连字符 `-`，扩展名固定小写 `.mp4`。原型出处：`tmp/prototype/clip-slicer/index.html` L119（`String(c.id).padStart(3,'0')+'-'+c.title+'.mp4'`）。
3. **序号。** 项目内从 1 开始单调递增，位数不足三位左侧补零（`007`）；满 1000 后自然变四位，不回绕、不截断。序号在切片记录落盘时分配并写进项目清单的计数器；生成失败不消耗序号；切片被删除、重新生成或项目重开都不回退、不复用。删除后留下的空号是允许的，它记录「这里曾经产出过一条切片」。
4. **标题清洗。** 新增一个只服务文件名的纯函数（暂名 `clipFileTitle`），按顺序执行：
   1. 把 `\ / : * ? " < > |` 每个字符替换成 `_`；
   2. 把 C0 控制字符（U+0000–U+001F）替换成 `_`；
   3. 不做 Unicode 规范化、不转小写、不删中文——全角标点（`？`、`：`、`／`、`｜`）在 Windows 与 macOS 上都合法，原样保留；
   4. 去掉首尾的空格与 `.`；
   5. 按码点截到 60 个字符（`Array.from` 计数，不切坏代理对），再执行一次第 4 步；
   6. 结果为空时用 `未命名`；
   7. 若 `<项目目录>/clips/<文件名>` 的 UTF-16 长度超过 240，继续缩短标题直到满足（至少保留 1 个字符），给 Windows `MAX_PATH` 留余量。
5. **保留设备名不用特判。** 文件名以 `<序号>-` 开头，Windows 的 `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9` 作为整段文件名永远不会命中，因此不额外加前缀或改写标题。
6. **不覆盖别人的文件。** 分配序号时若 `clips/` 里已存在同一 `<序号>-` 前缀的文件（用户手工放进来的、或旧记录残留），跳到下一个序号；仍然只增不减。
7. **记录沿用现有主题切片格式，不新增记录类型。** 仍写 `video.json` 里该主题的 `TopicClip`：`{ file, start, end, segmentIndexes, segmentOffsets }`（`packages/core/src/core/video-data.ts:18`）。项目切片的 `file` 存 `clips/` 内的文件名（如 `008-直播_复盘_ 3 个技巧_.mp4`），解析基准是项目的切片目录；非项目切片继续存 `topic.mp4`，解析基准仍是主题目录。没有新的项目级切片清单，也没有第二套切片 JSON。
8. **标题后续可改，文件名不改。** 主题改名只影响显示；已落盘的切片文件按记录里的 `file` 打开，不跟着改名，避免用户在 Finder / 资源管理器里正在用的路径失效（与 [ADR-0002](./0002-filesystem-and-json-storage.md)「路径一旦冻结就不再变」同一条原则）。

## 清洗示例

| 主题标题 | 清洗后 | 落盘文件名 |
| --- | --- | --- |
| `为什么你的选题没人看？` | 不变（全角 `？` 合法） | `007-为什么你的选题没人看？.mp4` |
| `直播/复盘: 3 个技巧?` | `直播_复盘_ 3 个技巧_` | `008-直播_复盘_ 3 个技巧_.mp4` |
| `"爆款"<标题>\|测试` | `_爆款__标题__测试` | `009-_爆款__标题__测试.mp4` |
| `结尾不能有点...` | `结尾不能有点` | `010-结尾不能有点.mp4` |
| `CON` | 不变（前缀已避开设备名） | `011-CON.mp4` |
| `   ` | `未命名` | `012-未命名.mp4` |
| 61 个汉字 | 截到 60 个汉字 | `013-<前 60 字>.mp4` |

## Considered Options

- **复用 `slugify`（`packages/core/src/core/paths.ts:9`）**：它转小写、把非字母数字压成 `-`、面向目录名与 URL 稳定；中文主题会被改成连字符串，丢可读性，且它不是为 Windows 文件名保留字与长度约束写的。切片文件名要给人看、要能按标题认出来，所以单独一个保留原文的清洗函数。
- **切片留在每个视频的主题目录**：产出分散在多个来源目录里，用户要跨目录翻；项目级的「打开切片目录」「切片产出」都失去单一根目录。不采用。
- **用时间戳或哈希做文件名**：天然唯一、天然合法，但目录里认不出内容，序号也不再表达生成顺序。不采用。
- **只在 macOS 上允许原始标题，Windows 另走清洗**：同一份项目换机器打开就出现两种文件名，记录要跟着平台变；一套清洗规则在两个平台都跑，行为可预期。不采用。
- **把标题放进子目录（`clips/<seq>/<title>.mp4`）**：多一层目录，用户点开切片目录看到的是序号文件夹而不是切片；平铺更直接。

## 后果

- 一个项目的全部切片在 `clips/` 下按序号平铺，序号即生成顺序，Finder / 资源管理器默认排序就是时间顺序。
- 序号有空洞（删除或失败）是正常状态；不要做「重排编号」的修复动作，那会让已冻结的路径失效。
- `TopicClip.file` 的含义从「主题目录内的文件名」扩展为「按所属容器解析的文件名」：项目切片相对 `<项目目录>/clips`，非项目切片相对主题目录。读侧要先知道这条记录属于哪个项目；旧的 `topic.mp4` 记录不受影响。
- 清洗只保证文件名合法，不保证跨平台大小写不冲突——序号唯一已经消除了同名冲突。
- 超长项目目录 + 长标题仍可能顶到 Windows 路径上限；240 的余量是保守值，不是硬保证，用户把项目放在极深目录时可能失败并报错，不做自动搬迁。

## Open Question

**每段切片前是否多留 2 秒（`CLIP_PREROLL_SECONDS = 2`，`packages/core/src/core/config.ts:5`）？** [ADR-0026](./0026-single-file-topic-clip.md) 为整段视频的笔记切片定了 2 秒前移；原型里项目切片直接等于所选字幕行的区间，没有前移（L104）。两种口径的差别是：沿用 2 秒 → 每段开头多出 2 秒画面、段偏移与前移后合并规则完全复用；正好等于字幕时间段 → 切片更贴字幕、但与现有切割逻辑分叉。

本 ADR 不决定这一点。在 Link 确认前，产品行为保持现状（`CLIP_PREROLL_SECONDS = 2` 不变），任何实现不得预设新行为；确认后以新的 ADR 或对本 ADR 的修订落定。
