# 分析与切片两条串行队列，可同时各跑一个

桌面端的任务执行器只有一条全局串行队列：`JobQueue` 用单个 `running` 槽位把 `extract`、`topics`、`notes` 三类任务排成一条（`apps/desktop/src/main/jobs.ts:5-8`、`:75-77`、`:92-120`），术语表把它写成「同一时刻只有一个任务在跑」。整理切片要把一次录屏持续拆成「字幕解析 + 主题分析」和「切片」两段工作：分析必须一直自动往前推，切片要看用户逐个确认主题。两者共用一条队列时，用户停在「确认字幕」弹窗上就堵住了后续分析，长时间直播的积压只会越拖越长；切片的转码与拼接也顺带占住了分析的空档。原型把两条队列做成各自一个 running 槽位、可同时各跑一个（`tmp/prototype/clip-slicer/index.html` L98 `activate`）。

已接受（accepted，2026-11-06，r77）。

## 决定

1. **任务按归属分成两条队列。** `analysis`：`extract`（转写 + 划主题）、`topics`（重划主题），以及整理切片里「一个字幕解析 + 主题分析」的分块任务；`slice`：`notes`（为选定主题生成笔记与切片），以及整理切片里「一个主题」的切片任务。归属只由任务种类决定，不由入口页面决定——「整理笔记」页触发的 `notes` 同样进切片队列。
2. **每条队列各自串行，两条可并发。** 每条队列同时至多一个任务处于 `running`；全局同时至多两个（每队列一个）。没有并发度设置，也没有「切换到单队列」的开关；这是执行器的固定形状，不是项目配置项。
3. **待确认主题不是任务。** `proposed` 主题只出现在待确认区，既不占分析队列也不占切片队列；阻塞它的只是用户自己，队列继续往前走。
4. **改名不改语义。** `JobQueue` 保留类名与 `enqueue` 入口，内部从单槽位改成两个槽位（`analysis` / `slice`）；`launchWorker`、进度事件、日志、取消路径都不变。执行器一次最多并行启动两个 worker 进程。
5. **运行锁仍是同一视频的写入门槛。** [ADR-0002](./0002-filesystem-and-json-storage.md) 的 `index.json` 与视频文档写法不变，术语表里的「运行锁」（`<输出目录>/.vnote-run.lock`）继续保证同一个视频不会有两个任务同时写。取任务时跳过目标视频正被另一任务锁住的任务，保持其余排队任务的相对顺序；两条队列因此可以在不同视频上并发，同一视频的分析与切片仍会先后执行。等待由持锁任务的结束自然解除，不引入新的锁层级。
6. **并发上限来自队列数量，不来自项目数量。** 跨项目不另开槽位：多个项目的任务排进同样的两条全局队列（跨项目调度不在本决定范围内）。
7. **取消按任务。** 取消一条队列里的任务不影响另一条队列正在跑的任务；任务浮层按任务分别显示，最多两个同时进行。

## Considered Options

- **保持单队列，靠优先级让分析插队**：不改执行器形状，但分析任务插队会把切片无限推后，或者切片插队把分析推后，等于把「两段工作都在推进」交给调度运气。整理切片要求分析无条件持续前进，切片分类独立节奏，优先级解决不了。
- **每条队列都可配置并发数（例如分析 2 + 切片 1）**：需求里没有并发设置（#121 Out of Scope），且本地 ASR 与 ffmpeg 都是重 CPU 任务，多开一条并行会直接抢算力；固定「各一」是唯一能保证界面可解释的上限。
- **按项目开队列**：每个项目两条队列会让并发随项目数增长，机器负载不可预期；跨项目调度也明确不在范围内。
- **把切片任务合并进 `notes` 的同一队列但允许两个 `running`**：仍然是全局槽位，无法表达「分析与切片各自串行」；任务种类不同、失败与取消语义也不同，按种类分队列更直接。

## 后果

- 整理切片期间，分析可以一直推进到待确认，不再被切片或被用户确认动作挡住；切片只在切片队列里按序执行。
- 两个 worker 可能同时跑（一个 ASR/LLM 分析、一个 ffmpeg 切片），CPU 与内存峰值高于现状；这是「分析不停」的代价，任务浮层与日志要能同时呈现两个任务。
- 同一视频的切片仍要等该视频的分析任务释放运行锁，所以「分析与切片同时跑」的可见收益主要出现在不同视频之间；同一视频的上限仍是串行。若将来把运行锁细分为按主题粒度，需要另开 ADR，不在本决定内。
- 术语表「生成任务」里「同一时刻只有一个任务在跑」的说法作废，改为按队列各自串行、两队列可同时各跑一个；`_Avoid_` 的旧措辞一并更新。
- 单队列时代的 `jobs.test.ts` 断言（第二个任务保持 `queued`）只在同一队列内继续成立；跨队列的并发需要新的断言，由实现票补齐，本设计票不改代码与测试。
