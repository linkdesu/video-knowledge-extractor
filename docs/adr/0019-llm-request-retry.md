# LLM 请求失败重试一次：超时与 5xx 不再直接作废整条流水线

打包试用版第一次在桌面端跑完 10 分钟视频的完整提取时，4 个主题里 2 个失败：`自媒体自动化与AI视频成本` 报 `The operation was aborted due to timeout`，`心理咨询智能体与知识库` 被连带标成「本次生成未完成」。同一条提示词（2291 字符）在测试脚本里 4.8 秒返回 200，紧接着重发同一请求 295 秒仍未返回。这个端点会偶发挂住，而 core 的 LLM 客户端一次请求只发一次，一次挂住就让整个任务变成「需重跑」。

## Status

已接受（accepted）。收紧 [ADR-0005](./0005-llm-notes-pipeline-and-corrections.md) 的错误处理：流水线级「一次失败即中止」不变，改成让单次请求自己重试。与 [ADR-0016](./0016-volcengine-flash-asr-provider.md) 的远程 ASR 重试判据同向（网络/超时/429/5xx 可重试）。

## 证据

- 运行：`bun run package:mac` 产出的 `Video Notes.app`（未签名），隔离 home/userData，本地 FireRedASR + `ai-02/qwen3.8-27b`。
- `input-600s`（10 分钟）完整跑完转写与说话人分离，83 条字幕、4 个主题；`topic-1`、`topic-2` 的笔记 2.5 秒级完成，`topic-3` 的要点请求在 180 秒上限处中止。
- 复现脚本 `tmp/r26-probe-slow-topic.ts`：`noteSystemPrompt(topic-3)` 38 条字幕、2291 字符；第一次 `HTTP 200 in 4787ms`，第二次同参数请求 295277 毫秒后仍未返回（Bun 的 fetch 先超时）。
- 失败形态对用户是双倍的：第一个主题超时后，`settleRunWhileLocked` 把还没跑的主题标成「本次生成未完成」，两个主题一起变成「需重跑」。

## 决定

- `createLlmClient` 的 `chat` 最多尝试 **2 次**（首次 + 重试一次），间隔 750 毫秒。
- 可重试：请求超时（`AbortError` / `TimeoutError`）、网络错误、HTTP 429、HTTP 5xx、空的补全结果。不可重试：其余 4xx（鉴权、参数、路径错误）与响应体不是 JSON。
- 「传输阶段」包含取响应头 **和读完响应体**：端点常先回 200 再挂住生成，超时落在 `res.text()` 上；只包住 `fetch()` 会漏掉正是这次遇到的形态。
- 单次尝试的超时仍是 **180 秒**，不因重试放宽；最坏情况一次调用 360 秒，用户可以取消任务。
- 超时错误改写为中文：`LLM 请求超时（180 秒内没有返回）：<base url>`。原生的 `The operation was aborted due to timeout` 不适合直接出现在笔记列表里。
- usage 只统计成功的请求；重试不计入 calls。

## Considered Options

- **把 180 秒上限调大（如 600 秒）**：治不了挂住——实测那次挂住超过 295 秒且没有恢复迹象；而且会把「偶发挂住」的等待时间放大三倍。
- **缩短单次超时到 60 秒 + 重试两次**：总预算和现在一样，但正常但较慢的生成（长主题一次要几十秒）会被误杀，没有证据支持这个上限。
- **在流水线层重试失败的主题**：重试需要重新进入 `settleRunWhileLocked` 的结算语义，还要决定「部分成功」的落盘状态；请求层重试不动这些契约。
- **失败后继续跑其余主题**：一处失败不再连带其它主题。这个改动要重定义 `settleRunWhileLocked` 的终态与 `video.json` 的 `status`，属于流水线语义变更，留待单独一轮。

## 后果

- 偶发挂住从「整个任务需重跑」降级为「多等 0.75 秒 + 一次重发」；真实故障仍然是 2 次后报中文超时错误。
- 重试会重复计费一次（提示词与可能的补全）。相比整条 10 分钟流水线重跑，代价更小。
- 端点持续 5xx 时，错误出现时间从 1 次请求推迟到 2 次；界面上的 `失败` 与错误文案不变（现在带中文超时说明）。
- 远程 ASR 的重试逻辑不受影响（它在 `volcengine.ts` 里自成一套）。
