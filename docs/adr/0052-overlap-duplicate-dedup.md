# r78 重叠段去重：时间重叠 + 文字包含才判重复

issue #97：连麦回声或分离模型的重叠检测会把同一句话识别两次，字幕里出现两行几乎一样的文本（Lab 标注分析里 42 对时间重叠段中 24 对是短段被长段整段包住）。PR #106 试过「只按时间与说话人判重、文字不参与」，会把不同语句误判成重复，已关闭。Link 11-04 确认：**在两段时间重叠的前提下**可以用文字相似判重。

## Status

已接受（accepted，2026-11-04，r78）。补充 [ADR-0046](./0046-r70-crosstalk-and-short-replies.md) 的重叠口径：抢话归属决定「哪些段不单独成行」，本单决定「已经成行的两句里，哪一句是回声重复」。

## 决定

1. **一条规则，一个实现。** `packages/core/src/asr/overlap-dedup.ts` 的 `dedupeOverlappingLines(rows)` 是唯一实现，阈值集中在 `OVERLAP_DEDUP_RULES`。
2. **两条同时成立才算重复：**
   - 时间重叠 ≥ 较短一行时长的 `minOverlapRatio`（默认 0.5）；
   - 短段归一化文本（`normalizeReplyText`：NFKC、大写、去标点空白符号）里至少 `minContainedRatio`（默认 0.8）能在长段文本中**连续**找到（最长公共子串 ÷ 短段长度）。
3. **只删短段、留长段。** 时长更长的行才叫「长段」；两行等长时都保留，不猜谁是真身。时间重叠但文字不同（真抢话）、重叠不足 50%、文字只部分相同，两行都留。
4. **无链式误删。** 按时长从长到短过一遍，只和已经留下的行比较：中间那段若自己也被更长的行吞掉，就不再拿它当依据删别的行；每条被删的行都由一条最终保留的更长行「包住」。
5. **两个调用点、同一函数。** 正式管线在 `pipeline/extract.ts` 落盘前对 `run.transcript.utterances` 跑一次（本地与远程 ASR 共用，日志记 `droppedOverlaps`）；Lab 组装在 `dev-lab/lines.ts` 的 `assembleLines` 里对最终行跑一次。两处不复制判定逻辑。

## Considered Options

- **只按时间与说话人判重（PR #106 的方案）**：会把「同一时间两人各说一句」误判成重复（Link 标为「误判重复」），已否决。
- **子序列/LCS 包含比例**：`我不知道` 会 100% 落在 `我知道你不知道` 里，误删不同语句；改用最长公共**子串**，要求 80% 的短句是长句里的连续片段。
- **归一化后完全相等才算重复**：ASR 对同一段回声的两次解码常差一两个字（`可以看到` / `可以看到。`、`嗯。` / `嗯。嗯。`），完全相等漏判太多。
- **按绝对秒数设阈值**：换音频就不成立；阈值全部用比例。
- **在 `filterFillerUtterances` 里顺手做**：那个入口的语义是「删掉不损失信息的短句」，去重的判据是「时间 + 文字重复」，混在一起会让模型批次与日志口径都变味；保持独立函数、相邻调用。

## r85 补充：区间重跑只追加新行（#129）

项目分析复用视频库字幕：来源视频通常已经整段转写过，项目再分析其中一块时，ASR 会把这块重跑一遍。原来的追加是无条件的，同一句话因此在字幕里出现两次（`tmp/verify/r85-queue-confirm-tab-2/` 的一次验收里，10 分钟区间显示「完整字幕 179 行」，实际只有 89 句，其余是整行重复）。确认字幕弹窗要把「来源视频当前已知的全部字幕」列出来，重复行会让用户在同一句话上勾两次、已选计数也翻倍。

- 新函数 `dropCoveredDuplicates(existing, incoming)`，与 `dedupeOverlappingLines` 同模块、同一组阈值；`project-analysis.ts` 的追加处是唯一调用点，Lab 与 `extract.ts` 不受影响。
- 只判一个方向（新行 ⊆ 旧行）：时间重叠 ≥ **新行**时长的 `minOverlapRatio`，新行至少 `minContainedRatio`（0.8）能连续落在旧行里。再满足这几条才丢新行：落在**最长公共子串之外**的字不超过 4 个（`MAX_UNMATCHED_CHARS`）；新行多出字时旧行必须以收尾标点结束（`SENTENCE_END`）且多出的字全是叹词（`FILLER_CHARS`）；旧行紧贴匹配段外面不能是数值语义字符（符号贴着数字被切在匹配段外，见下文）。
  - 只看「没出现的字数」不够：三四个字的短句只要时间重叠就全数命中（旧行「今天讨论素材整理」vs 新行「三百块」没一个字相同也 ≤4；旧行「五百块」vs 新行「三百块」只差一个字，金额却被当重复删掉）。
  - 只看比例也不够：归一化已经去掉标点，剩下的每个字都是内容。旧行「建议这样操作」vs 新行「不建议这样操作」包含比例 0.857、只差一个「不」，语义却相反；实词、否定词、数字的差异一律按新内容保留，只有「啊/哦」这类叹词算重跑噪音（旧行「今天讨论素材整理」vs 新行「今天讨论素材整理啊」仍然丢掉）。
  - 语气词白名单按单字判断，分不清词尾与语气词：旧行「今天的目的地就是酒」vs 新行「今天的目的地就是酒吧」里，多出来的「吧」属于地名，删掉就是永久丢内容。旧行带**句子终止标点**说明那句话本来就说完了（真实素材 360 行转写只有「。」与「？」），但「说完了」只证明**前一句**说完了，证明不了新行多出来的字是语气词——`吧` 在 `酒。`→`酒吧。` 里同样是句末字。所以白名单只收**叹词**（`嗯呃啊呀哦噢喔唉哎诶欸`）；`吧`「酒吧」、`呢`「华达呢/花呢」、`嘛`「喇嘛」、`啦`「哗啦」、`咯`、`喽`、`哈`「哈哈」、`呵`、`喂`「喂饭」、`嘿`、`嗨`、`额`「金额」、`恩`「报恩」这些能收在实词词尾的字一律不算。分不清就保留新行，宁可多一条近似重复行，不能永久吞掉词尾（#144）。旧行停在实词中间（没有终止标点）同样保留新行。
  - 「说完了」只认终止标点（`SENTENCE_END` = `。！？!?…`）：逗号、顿号、分号只分隔分句，旧行「…就是酒，」vs 新行「…就是酒吧。」里「吧」仍是词尾，同样必须保留。终止标点外面可能包着引号、括号或跟空白（`「…酒吧。」`、`…酒吧。 `），判断时跳过这些装饰（`TRAILING_DECORATION`）；不跳过它们，这些行的语气词容忍会整体失效，重跑重复行会回到字幕里。
  - 用旧行字符集判断「这个字出现过」同样不够：旧行「不会亏钱，建议这样操作。」vs 新行「不建议这样操作。」里的「不」在旧行开头出现过，包含比例 0.857、只差一个字，却把相反的建议丢掉。判据只能看公共子串之外那几段本身是不是语气词，最长公共子串因此要返回匹配位置。
  - 比例门槛来自 `dedupeOverlappingLines` 的同一组规则；短语气词（「嗯。」）归一化后完全一致，不受影响。
  - 判重文本不能直接用 `normalizeReplyText`：它把 `\p{P}\p{S}` 全删掉，「预算是3.5万元」与「预算是35万元」、「收益率是-5%」与「收益率是5%」、「5%」与「5」都成了同一串文本，重跑把金额、正负、单位听错时新行会被静默丢掉。`dropCoveredDuplicates` 因此用 `dedupText`：丢掉纯装饰的标点与空白，数值语义相关的字符保留——**紧邻数字的标点**（`.` `+` `-` `%` `/` `:`）与**全部 `\p{S}` 符号**（`$` `€` `¥` `°` `×` …）。
  - 符号整类保留的理由：哪几种符号会改变数值含义（货币、度数、乘号、约等号）枚举不干净，装饰性标点在 `\p{P}` 里、照旧丢掉，所以留 `\p{S}` 是保守且可维护的边界。旧行「预算是$500。」vs 新行「预算是€500。」、旧行「收益率是5%。」vs 新行「收益率是−5%。」（U+2212）必须都保留新行，否则重跑把金额币种、正负听对的内容被当重复删掉（#144 缺陷 1）。
  - **符号保留下来不等于「含义不同必留新行」**：新行整句落在旧行里时（未匹配 0 字），旧行可以把符号切在匹配段外面——旧行「−5%是这次的收益率。」vs 新行「5%是这次的收益率。」、旧行「£500是本次预算。」vs 新行「500是本次预算。」、旧行「温度测量结果是30°。」vs 新行「…是30。」。所以还有一道边界判据：旧行紧贴匹配段起点前或终点后的字符是数值语义字符（`isNumericSemantic`）时，保留新行。
  - 边界判据必须在**原文**上看，不能在 `dedupText` 结果上看：丢逗号后「收益率是5%，今天讨论素材整理。」里的 `%` 看似紧贴「今」，按去标点文本判会把上一分句的符号算到新行头上，正常重复行（重跑出来的「今天讨论素材整理。」）就不再被丢掉。`dedupText` 因此同时返回每个保留字符在原文里的下标，边界判断用 `rawIndex` 取旧行原文字符。
  - 达到最长长度的匹配可能不止一处：旧行「−5%是这次的收益率，后来5%是这次的收益率。」里第一处匹配前面带负号，第二处才是覆盖新行的同句重复。最长公共子串返回**全部**等长匹配，任何一处通过边界与叹词判据就丢新行；只看第一处会让结果依赖两处的先后顺序。
  - 旧行**别处**的数字与符号不参与（旧行「预算是3.5万元，今天讨论素材整理。」「收益率是5%，今天讨论素材整理。」「今天讨论素材整理，£500是本次预算。」照旧判重复）。
  - 等价的负号写法先归一：NFKC 不折 U+2212，`−`、`‐`、`–`、`—`、`―`、`﹣` 一律折成 ASCII `-` 再判重，同一句话的两种写法仍是同一行（不会因为符号写法差异多出一行），而 `-5` 与 `5` 依旧不同。
  - 已声明的取舍：判重文本丢标点，所以「你明天来？」与「你明天来。」同形，疑问句式的差异不参与判重（同一句回声里标点本来就会变）；NFKC 会把 `①`、`％`、`⒈`、`5²` 折成普通数字形态，上标与普通数字同形（真实字幕里几乎不出现）。两者都是 `normalizeReplyText` 一脉相承的口径，本票不改。
  - 不能改成「整行数字列表必须相等」：旧行「预算是3.5万元，今天讨论素材整理。」里的数字在新短句范围之外，要求相等会让「今天讨论素材整理」重跑后被当新内容再追加一遍。数字放进文本参与包含判据，范围外的内容自然不参与；新行多出 `%`、`.` 这类字符时，它们落在公共子串之外、又不是叹词，按新内容保留。
  - 说话人是行的身份：抢话时两个人可能在**同一毫秒区间说同一句话**（`dedupeOverlappingLines` 只删严格更短的行，两行都留在字幕里），跨次追加只看文本会把另一个说话人的新发言当重复删掉。两侧都带 `speakerId` 且不同时一律保留新行；任一侧缺失才回落到纯文本判据。
- 已有行一律保留：主题里的行 id 与弹窗里已勾选的行都按行内容定位，删旧行会让已产出的主题引用错位。
- 新行比旧行多出超过 4 个字（重跑解码多出的半句）必须保留，否则重跑区间会永久少字幕。
- 与 `dedupeOverlappingLines` 的「留长删短」相反，这里删的是新来的重复行。两者共用同一组时间重叠与包含比例阈值，但判据不同：`dropCoveredDuplicates` 另加「未匹配字数 ≤ 4 + 全是语气词 + 旧行带收尾标点」三道闸，取舍方向也相反，因为一个在落盘前、一个在追加前。

后果：区间重跑不再改动已有行 id，`addedLines` 只统计真正新增的行；弹窗里的「完整字幕」与字幕文件一致。

字幕行 id 还要区分**字段完全相同**的历史行：旧版无条件追加会把同一句字幕存成两份时间、说话人、文本都一样的行，只按字段哈希会让两行共用一个 id，弹窗里勾一行联动两行、提交也只解析得出一行。`lineIdsOf` 因此按数组顺序数出现次数，第 2、3…次出现追加 `-2`、`-3` 后缀；`lineIdsFor`（主题）与 `subtitleLinesFrom`（弹窗）共用这一个函数，两边算出的 id 必然一致。

## r90 修正：判重文本保留数值语义，语气词只认叹词（#144）

#129 落地后的只读评审（`tmp/handoff/spec-121-SolReview129.md` 缺陷 1、2）指出两处仍会静默丢内容，本票按下面的方向收紧。所有改动都只把判据往「保留新行」的方向推，不新增任何删除路径。

- **符号**：`dedupText` 原来只留 ASCII 的 `.+-%/:`，`−5%`（U+2212）与 `5%`、`$500` 与 `€500` 归一后同形，新行被当重复删掉。改为全留 `\p{S}`，并先把与 `-` 同义的连字符/减号归一，保证「写法不同、含义相同」仍是同一行。
- **匹配边界的符号**：只留符号还不够——新行整句落在旧行里时，符号可能被切在匹配段外面（旧行「−5%是这次的收益率。」vs 新行「5%是…」）。旧行紧贴匹配段起点前/终点后是数值语义字符时保留新行。
- **语气词**：`FILLER_CHARS` 只留叹词（`嗯呃啊呀哦噢喔唉哎诶欸`）。旧行带句号只说明旧句说完了，证明不了新行多出的字是语气词；`酒。`→`酒吧。`、`华达。`→`华达呢。`、`喇。`→`喇嘛。`、`哗。`→`哗啦。` 里多出的字都是词的一部分，删掉即永久丢内容。代价是重跑补齐句末「吧/呢/嘛/啦」这类语气词时会多留近似重复行，接受：多一行可见，少一句不可见。真实素材统计见测试证据节的冒烟数据。
- **边界判据第二轮修正**：第一版在 `dedupText` 结果上看邻接字符，把被逗号隔开的上一分句符号（旧行「收益率是5%，今天讨论素材整理。」的 `%`）当成了新行的符号，正常重复行不再去重；且只认第一处等长匹配，旧行「−5%是这次的收益率，后来5%是这次的收益率。」的结果依赖两处先后顺序。现在边界按原文下标判断，并且遍历所有等长匹配。
- 评审同时指出 `dedupeOverlappingLines`（#97 落盘前判重）仍用 `normalizeReplyText`，同一模块两条路径的判重文本口径分裂：那属 #97 的行为，本票不改，记为 proposed ticket。另一处已知残留：数字被截断（旧行「−1500是本次预算。」vs 新行「500是本次预算。」、旧行「…是300°。」vs 新行「…是30。」）仍会判重复——那是 #129 就存在的判据形态，同样记 proposed ticket。
- 说话人身份的跨次对齐（评审缺陷 3）不在本票范围，见 #145。
