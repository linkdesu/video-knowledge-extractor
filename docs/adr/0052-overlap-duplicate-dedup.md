# r78 重叠段去重：时间重叠 + 文字包含才判重复

issue #97：连麦回声或分离模型的重叠检测会把同一句话识别两次，字幕里出现两行几乎一样的文本（Lab 标注分析里 42 对时间重叠段中 24 对是短段被长段整段包住）。PR #106 试过「只按时间与说话人判重、文字不参与」，会把不同语句误判成重复，已关闭。Link 11-04 确认：**在两段时间重叠的前提下**可以用文字相似判重。

## Status

已接受（accepted，2026-11-04，r78）。补充 [ADR-0046](./0046-r70-crosstalk-and-short-replies.md) 的重叠口径：抢话归属决定「哪些段不单独成行」，本单决定「已经成行的两句里，哪一句是回声重复」。

## 决定

1. **一条规则，一个实现。** `packages/core/src/asr/overlap-dedup.ts` 的 `dedupeOverlappingLines(rows)` 是唯一实现，阈值集中在 `OVERLAP_DEDUP_RULES`。
2. **两条同时成立才算重复：**
   - 时间重叠 ≥ 较短一行时长的 `minOverlapRatio`（默认 0.5）；
   - 短段归一化文本（`normalizeReplyText`：NFKC、大写、去标点空白符号）里至少 `minContainedRatio`（默认 0.8）能在长段文本中**连续**找到（最长公共子串 ÷ 短段长度）。
3. **只删短段、留长段。** 时长更长的行才叫「长段」；两行等长时都保留，不猜谁是真身。时间重叠但文字不同（真抢话）、重叠不足 50%、文字只部分相同，两行都留。
4. **无链式误删。** 按时长从长到短过一遍，只和已经留下的行比较：中间那段若自己也被更长的行吞掉，就不再拿它当依据删别的行；每条被删的行都由一条最终保留的更长行「包住」。
5. **两个调用点、同一函数。** 正式管线在 `pipeline/extract.ts` 落盘前对 `run.transcript.utterances` 跑一次（本地与远程 ASR 共用，日志记 `droppedOverlaps`）；Lab 组装在 `dev-lab/lines.ts` 的 `assembleLines` 里对最终行跑一次。两处不复制判定逻辑。

## Considered Options

- **只按时间与说话人判重（PR #106 的方案）**：会把「同一时间两人各说一句」误判成重复（Link 标为「误判重复」），已否决。
- **子序列/LCS 包含比例**：`我不知道` 会 100% 落在 `我知道你不知道` 里，误删不同语句；改用最长公共**子串**，要求 80% 的短句是长句里的连续片段。
- **归一化后完全相等才算重复**：ASR 对同一段回声的两次解码常差一两个字（`可以看到` / `可以看到。`、`嗯。` / `嗯。嗯。`），完全相等漏判太多。
- **按绝对秒数设阈值**：换音频就不成立；阈值全部用比例。
- **在 `filterFillerUtterances` 里顺手做**：那个入口的语义是「删掉不损失信息的短句」，去重的判据是「时间 + 文字重复」，混在一起会让模型批次与日志口径都变味；保持独立函数、相邻调用。

## 后果

- 路飞样本（Lab 缓存，当前 refine 标签，1843s）：295 行 → 293 行，删掉 2 行，都是被更长一行 100%/80% 包住的回声（645.06s「嗯。」、941.91s「好，谢谢谢谢。」）。标注掉行 2 条（都是这两行的 B 标记），无「误判重复」标记受影响。
- 15:37「好的话。」：当前 main 的 `assembleLines`（#104 的 `resolveCrosstalk` 在前）在去重之前就已经把这句并进了 0.25s 插话段并整段丢弃，本单不改变这一点（去重前后都没有这一行）。见 PR 的已知问题。
- 另外两段中文音频（607s 双人讲解、600s 四人录音）：607s 那段去重 0 行；600s 那段删 1 行——44.01s 的 1.08s 附和「就是这个。」，文字 100% 落在对方 37.81s 起的长句里，属规则内的回声判重。两段都没有带事实/观点/承诺的句子被删。
- 正式管线 `video.json` 的 `transcript` 会少掉回声行；主题划分、主播识别、生成笔记读到的是去重后的版本。`edits` 里按行号的结构编辑使用可变副本，不受影响。
