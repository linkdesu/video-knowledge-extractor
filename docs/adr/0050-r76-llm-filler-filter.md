# r76 空洞短句：规则过滤之后，把剩下的短句整批交给模型判

#109 的验收反馈来自 r70 之后仍留在字幕里的行：「OKKAYK。」「哈LL喽你好。」「嗯，喂，你好。」「呃，你好，你好，能听见吗？」。它们都不是 `SHORT_REPLY_RULES` 能写全的形态——识别乱码与串词无法靠词表穷举，寒暄的排列组合又太多。规则只管「整行就是一声附和」的确定性形态；语义上「删掉不损失信息」要靠模型判，但绝不能一句一次请求（一小时的视频几百行，会把端点和时间都耗光）。

## Status

已接受（accepted）。补充 [ADR-0046](./0046-r70-crosstalk-and-short-replies.md) 决定 3 的**调用位置**（规则本身与 `SHORT_REPLY_RULES` 不变）：过滤不再发生在本地 ASR 引擎里，而是统一在 `runExtract` 落盘前跑一次。

## 决定

1. **一个入口：`pipeline/filler-filter.ts` 的 `filterFillerUtterances`。** 内部两段、顺序固定：先跑既有的 `filterShortReplies`（`SHORT_REPLY_RULES`），再把剩下的短句交给模型。调用方只认这一个函数，规则判定没有第二份实现。
2. **位置改到 pipeline、落盘之前。** 过滤后的字幕就是写进 `video.json` 的 `transcript`，后续划主题、生成笔记、重渲染都读这一版；远程 ASR（火山）也因此获得同一份过滤。`asr/local.ts` 里原来那次 `filterShortReplies` 调用随之删除——放在引擎里既覆盖不到远程引擎，又让「规则 + 模型」分成两处。
3. **一次请求一整批。** 每批 `FILLER_BATCH_SIZE = 40` 条，提示词里是「序号. 文本」的列表，要求模型只回 `{"drop":[number]}`（元素也可写成 `{"index","reason"}`），编号必须来自该批列表。批内序号与全局行号的映射在代码里做，`FillerBatchLog` 同时记 `sent`（整批行号）、`rows`（被丢弃的行号）、`drop`（批内序号）、`texts` 与被截断的 `reasons`。
4. **候选闸门：仍然得是「短句」。** 规则没删掉、且时长 ≤ 8s、归一化后 ≤ 24 字才进请求；更长的行一律保留、不送模型。这一层是成本闸门也是误删闸门：有内容的长句根本没有被模型看到的机会。
5. **失败只影响该批。** 端点报错、超时、回复不是 `{drop:[...]}`（缺 `drop` 数组、不是对象、不是 JSON）都只是「本批不过滤」：行原样保留、`warn` 一条 `填充语过滤跳过本批`（带 batch / batchSize / sent / error），导入继续。单条不合法（越界、重复、非整数）只丢那一条判定，不整批作废。
6. **提示词可覆盖。** 新增提示词 id `filler-filter`（`PROMPT_SPECS` 里可编辑，输出契约 `{"drop"`），渲染走 `renderPrompt`/`promptFingerprint`，与其它步骤同一套版本日志。

## Considered Options

- **每句一次请求**：直接违反 #109 验收 1，且一小时的视频要几百次往返。否决。
- **把所有行（不限长短）都交给模型判**：提示词体积与误删风险都不可控，模型看到长句就有机会把有内容的行点掉。只判短句，长句直接保留。
- **在 `asr/local.ts` 里调模型**：ASR 引擎拿不到 LLM 端点与客户端，远程引擎也复制不到这段逻辑；而且引擎带缓存，命中时不重跑会让过滤结果取决于缓存状态。挪到 pipeline 后一次落盘、一次判定。
- **给这一批判定加缓存**：`extract` 每个视频只跑一次，重导入才会再问；一次导入通常 1–2 批。为省这点请求新增 cache step、失效键与「坏回答不进缓存」的判据不值当。规则阶段本来就是纯函数，不需要缓存。
- **要求模型逐条给理由**：能提高可解释性，但会拉长补全、增加格式失败率。改为「理由可选」：给了就记进日志，没给也能靠 `texts` 解释每条决定。

## 后果

- 规则表外的噪声只有在闸门内（≤8s、≤24 字）才会被模型删；更长的乱码行仍会留在字幕里。这是刻意取舍：闸门外的一律当有内容。
- 每次导入多 1–2 次 LLM 请求（一批 40 条），耗时记在 `timings["filler-filter"]`；模型不可用时该步耗时只在重试窗口内，导入不失败。
- `filterShortReplies` 从 `asr/local.ts` 移出后，Lab 的 `refine_filter` 视图判定不变（本来就调 `isShortReplyLine`），但 Lab 侧看到的原始行不再被引擎预先删掉——行视图与时间轴各自按开关判定，口径比之前更一致。
- 单测只用假客户端（`filler-filter.test.ts` 覆盖分块、批内序号映射、失败与格式回退、候选闸门、日志字段），不调用真实模型；`extract.test.ts` 里一条端到端用例用注入的假 ASR + 假客户端断言 `video.json` 里的字幕已经被过滤。
