# r35 打磨：日志归属、说话人合并、主题完成态与失败闭环

r35 的七项反馈都来自打包版实测：日志与用户数据分居两处，说话人只能改名不能合并，主题完成态与切片文件不一致，视频无法删除，失败后卡片停在处理中，前置条件一次只报一个。这些不是七个独立小修，而是同一条原则的六个切面：界面显示的每个状态都必须由磁盘上的真实产物推导，用户能看到的每个对象都必须能完整管理。

## Status

已接受（accepted）。补充 [ADR-0014](./0014-desktop-ui-from-ux-prototype.md) 的库卡片状态规则、[ADR-0025](./0025-generate-notes-after-topic-confirmation.md) 的主题生成流程、[ADR-0028](./0028-structured-logging-and-windows-build.md) 的日志目录约定。

## 决定

1. **日志放在 `<notesRoot>/.logs`。** 主进程启动时按有效设置求值，设置页切换 `notesRoot` 后重新配置 logger；日志写入、设置页展示、「打开日志文件夹」、「复制诊断信息」与 worker 的 `logDir` 跟随同一个函数 `logDirFor(notesRoot)`。用户把笔记根目录备份或迁移时，日志一起走。
2. **说话人合并只改映射，不动原始数据。** `Speaker` 增加 `mergedInto` 与 `customName`；合并把其它说话人的 `mergedInto` 指向存活者，字幕行的 `speakerId` 与原始说话人记录保持不变。显示名沿映射链解析，撤销合并只清空 `mergedInto`。合并或撤销后若已有 `done` 主题，写 `speakerChangedAt`，主题页与笔记页显示「说话人已变更，可重新生成」；重新生成成功后清空。这样撤销永远无损，LLM 也不会被自动重跑。
3. **主题 `done` 必须同时满足 `topic.md` 与 `topic.mp4`。** 读侧用 `projectTopicArtifacts` 检查 `<outputDir>/<dirName>/topic.mp4` 是常规文件且大小大于 0；缺失或为空时投影为 `needs-rerun`、清空失效切片元数据，不写回磁盘。零时间段的主题在生成时直接报错，不再写出没有切片的笔记。用户点「单独重新生成」走 `force` 路径，`done` 主题也会重切并重写。
4. **删除视频先收任务再删产物。** 删除接口取消该视频的排队与在途任务，等队列排空后删除输出目录、该视频的缓存目录与 `index.json` 条目。源视频不在 notes 根目录内，永不删除。
5. **失败是持久化状态，不是瞬时提示。** `VideoData.failure` 记录最近一次失败的短原因与时间。worker 交付错误或异常退出时写入，新任务启动或成功完成时清除，取消不写。库卡片据此显示红色「失败」、原因与「重试」，重启后仍然成立。
6. **前置条件一次列全。** 入队门禁收集 LLM 端点、ASR 提供方、本地模型包与队列占用四类问题，用 `formatPrerequisiteError` 合成一条多行消息。用户修一次配置就能再次尝试，不必逐个撞错。
7. **空候选下拉框必须有话说。** 模型名候选为空，或输入过滤无匹配时，浮层显示明确提示而不是空壳；展开时始终列出全部已拉取候选，只有用户输入才过滤。

## Considered Options

- **合并时重写字幕的 `speakerId`**：撤销需要保存整份旧字幕快照，任何后续编辑都可能让快照过期。映射链让撤销只清一个字段，采用。
- **主题完成后单独异步切切片**：状态与文件可能短暂不一致，正是本次反馈的来源。保持切片先于 `topic.md` 的串行顺序，并在读侧校验文件，采用。
- **失败只存在 JobSnapshot 里**：卡片状态由磁盘文档推导，进程重启后快照消失。把失败写进 `video.json`，采用。
- **删除时直接删目录、不等任务退出**：在途 worker 会在删除后继续写锁与产物，留下孤儿目录。先取消并排空，采用。

## 后果

- 旧数据里只有编号切片、没有 `topic.mp4` 的主题会显示为 `needs-rerun`。这是真实状态，重新生成一次即补齐。
- `topic.mp4` 的可用性检查发生在读取路径，`listLibrary` 会为每个 `done` 主题 `stat` 一次文件。库规模在本地工具的量级内，可以接受。
- 日志目录跟随 `notesRoot` 后，切换根目录不会迁移旧日志；旧目录里的 7 天日志留给用户自行清理。
