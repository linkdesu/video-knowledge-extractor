# r37 打磨：本地模型只做检测、生成轨迹落盘、笔记进度与门禁

r37 的七项反馈同样来自打包版实测：在线下载模型经常卡死且下载中点不了取消，导入压缩包又分不清四个子模型的对应关系；重启后点「生成笔记」静默显示「完成：主题 0，笔记 0」；主题卡片和右下浮层的进度条没有意义；`topic.md` 正文只有说话人和文字，没有时间；合并说话人的弹窗被侧栏卡片裁掉按钮；笔记全都失效时仍能点进「笔记」步骤，而「单独重新生成」按钮却放在左下角的播放器下面。这些也不是七个独立小修，而是三条原则的切面：界面上的每个状态都必须能对上磁盘事实，不可用的入口必须关掉而不是报了再失败，每一次生成都必须留下可复盘的证据。

## Status

已接受（accepted）。补充 [ADR-0021](./0021-explicit-model-download-with-phase-log.md) 的模型管理入口、[ADR-0025](./0025-generate-notes-after-topic-confirmation.md) 的生成流程、[ADR-0029](./0029-r35-polish-speaker-merge-and-failure-loop.md) 的读侧产物投影口径。

## 决定

1. **本地模型只做目录展示与检测，不再提供在线下载与导入。** 设置页删掉「下载模型」「取消」「导入本地模型」与下载进度条、下载日志，只保留模型目录完整路径、「打开模型目录」和唯一的「检测本地模型」。检测的对象是流水线真正会加载的四个模型组：识别（`sherpa-onnx-fire-red-asr2-ctc-zh_en-int8-2026-02-25/` 下的 `model.int8.onnx` 与 `tokens.txt`）、说话人分离（`sherpa-onnx-pyannote-segmentation-3-0/model.onnx`）、说话人嵌入（`3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`）、标点（`sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12/model.onnx`）。文件清单直接取运行时用的 `modelFileSpecs`，只新增一层分组与文案，避免两份清单漂移。进入设置页与主进程启动各检测一次。
2. **每个主题目录落 `trajectory.json`，历史只增不删。** 路径是 `<outputDir>/<topicDir>/trajectory.json`（当前布局里主题目录直接位于输出目录下，没有额外的 `topics/` 层级）。结构固定为 `{ topicId, topicTitle, updatedAt, latest, history[] }`：每次首次生成、重新生成或说话人变更后的重跑都往 `history` 末尾追加一条，`latest` 指向最新一条，`history` 不设上限。一条记录包含 `runId`、起止时间与耗时、`trigger`（`initial` / `regenerate` / `speaker-changed`）、请求（`baseUrl`、`model`、`messages`、`glossaryCount`）、响应（`succeeded` / `failed`、`rawText`、`parsedSummary`、`error`）与切片状态。失败的运行也记一条，`status` 为 `failed`。请求结构里没有 API Key 字段，端点对象也不整体展开，密钥永不落盘。
3. **待生成主题的口径只有一处。** 界面读到的是经过 `projectTopicArtifacts` 投影的文档（缺 `topic.mp4` 的 `done` 主题读作 `needs-rerun`），而 `runNotes` 之前用未投影的 `loadVideoData` 过滤，于是按钮说「3 个新主题」，主进程却把三个都当 `done` 滤掉，返回「完成：主题 0，笔记 0」。现在 `runNotes` 在过滤前做同一次投影，界面与流水线看到同一组状态。过滤后队列为空时直接报错「本次没有需要生成的主题：所选主题均已生成完成」，不再写 `index.md` 后返回 0。LLM 返回无法解析的要点 JSON 同样记为失败，而不是当作空要点静默通过。
4. **进度只说真话。** 主题卡片与右下浮层都不再渲染百分比和进度条；卡片按主题真实状态显示「正在生成中… · 已用 MM:SS」「排队等待中…」「已完成」「生成失败：<原因>」，浮层显示「正在生成中（n/m）：<主题名> · 已用 MM:SS」，其中 `n` 是当前主题在本批里的序号。原因是 LLM 阶段没有可信的百分比，切片阶段的段数比例又不能代表整篇笔记的进度，画出来只是装饰。
5. **不可用的步骤先关门。** 顶部「3 笔记」在没有一个 `done` 主题时置灰禁用，鼠标悬浮提示「请先在「主题」步骤生成笔记」；进入笔记页的唯一条件是至少一篇笔记就绪，而不是「主题存在」。
6. **重新生成属于主题卡片。** 左下角的「单独重新生成」删掉，改为每张主题卡片上的「重新生成」，任何状态都可点、可重复点，生成中显示「生成中…」并禁用；每次都由 `force` 路径重跑该主题，并在该主题目录的 `trajectory.json` 里追加一条。
7. **弹窗挂在 body 上。** 合并说话人的确认框改用 `createPortal(..., document.body)`。`.vn-card` 的 `backdrop-filter` 会为 `position: fixed` 的后代建立包含块，所以挂在卡片内部的全屏遮罩会被裁在这张窄卡片里，下方的确认按钮因此不可见。
8. **`topic.md` 正文与字幕页同构。** `## 正文` 下每条字幕一行：`- [MM:SS] **说话人名称**：字幕文本`，时间达到一小时后用 `HH:MM:SS`。不再把相邻同说话人的句子合并成一条，因为正文要能按句定位到原片。

## Considered Options

- **保留在线下载，只是把取消按钮修好**：网络不通时下载本身就是死路，且四个子模型的目录关系无法由用户从压缩包推断。删掉下载，让用户把离线模型放进已知目录并由程序检测，采用。
- **`trajectory.json` 只保留最新一次**：用户会连续重跑做对比，只留最新一次就失去了对比的意义。改为 `latest` + 无限 `history`，采用。
- **在 `runNotes` 里为「无需生成」返回一个成功但空的结果**：这正是本次要被消灭的静默失败。空队列一律报错，采用。
- **给 LLM 阶段编一个假进度**：没有可信数据源，只会让用户误判卡死。改为纯文本状态与已用时间，采用。
- **用 `git` 提交号或运行号给 `trajectory.json` 分文件**：主题目录下的固定文件名才能被一个 `readdir` 找全，也让用户能直接打开最新一条。固定 `trajectory.json` + 内部 `history`，采用。

## 后果

- 升级后设置页不再有下载入口。已有模型目录的用户不受影响；缺模型的用户需要自己把四个模型放到 `<模型目录>`，检测卡片会指出每个缺失的相对路径。
- 旧主题目录里没有 `trajectory.json`，第一次重新生成时创建，`history` 从 1 开始。旧 `topic.md` 里的正文仍是旧格式，重新生成一次即整体覆盖为新格式。
- `history` 只增不删，一个被反复重跑的主题会持续变大。单条记录是本批的提示词与模型原文，量级在 KB 级，本地工具可以接受。
- 所有被选中的 `done` 主题在界面与流水线两侧现在口径一致；代价是 `runNotes` 每次多 `stat` 一遍各主题的 `topic.mp4`，与 `listLibrary` 已有的成本同级。
