# 每一步按输入哈希落盘缓存，主题编辑只重算受影响部分

三步里转写最贵，其次是每个主题的笔记；用户改一个词条或一个主题，都不该重跑全流程。所以缓存以“步骤 + 输入哈希”为单位落盘，失效范围由真实输入决定。主题在自动结果之上允许人工编辑，编辑与缓存分开存，重算不得覆盖编辑。

## Status

已接受（accepted）。存储形态遵循 [ADR-0002](./0002-filesystem-and-json-storage.md)：缓存是文件，不是数据库。

## 决定

- **缓存单位**（Q17）：转写（按分块）、纠错替换后的字幕、每块的候选主题、每个主题的笔记与切片。每项以输入内容的哈希为键落盘。
- **失效范围**（Q15、Q17）：改纠错词表 → 只重做字面替换与受影响主题的笔记，不重转写；改端点或模型 → 候选主题与笔记重做，转写与替换保留；某个分块转写失败 → 只重跑该块（Q14）。
- **主题编辑**（Q16）：自动检测出的主题可在界面里改名、合并、拆分、调整时间段，并选择哪些主题生成笔记。
- **编辑独立于缓存**：编辑作为持久记录保存，不写进缓存；缓存重算不得覆盖用户编辑。
- **最小重算**（Q17）：改一个主题 → 只重生成该主题的笔记与切片，其余主题沿用缓存；合并或拆分后，新主题的笔记与切片作废重算，被并入的旧主题记录删除。

## 后果

- 哈希必须覆盖真实输入：分块音频、识别模型、提示词模板、端点模型名、词表内容。漏一项就会出现“改了没生效”的假命中。
- 编辑层与缓存层要能分别丢弃：用户需要“丢弃编辑、回到自动结果”的路径，否则编辑会永久压住重算。
- 输入一变，旧缓存仍留在磁盘上占用空间；按主题找笔记时要能忽略过期目录。

## 未决问题

旧缓存与过期主题记录的清理策略未定；先不自动删除，避免误删用户还在用的切片。
