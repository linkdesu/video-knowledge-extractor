# 笔记生成走单一 OpenAI 兼容接口，分块出候选主题后全局合并

主题分析与生成笔记是仅有的两个模型环节。工具不该替用户决定用云端还是本地模型，所以只暴露一个 OpenAI 兼容端点；但长视频的整篇字幕塞不进一次请求，主题又必须跨块统一，因此沿用转写的分块：每块先出候选主题，再全局合并。纠错词表既是转写后的修正，也是让模型写对术语的提示，一并放进这条流水线。

## Status

已接受（accepted）。与 [ADR-0001](./0001-chunked-transcription-of-long-videos.md) 的分块粒度一致；[ADR-0003](./0003-asr-engine-firedasr-ctc.md) 关于纠错词表是必需手段的结论继续有效。

## 决定

- **单一端点**（Q13）：设置里只配一个 OpenAI 兼容端点：base URL、API key、模型名。云端还是本地由用户决定，工具不做区分、不做多端点路由。
- **串行**（Q13）：转写、主题分析、生成笔记依次执行；主题分析与生成笔记不与本地 ASR 并发，也不假设端点能承受并发请求。
- **分块复用**（Q14）：主题分析按分块逐块产出候选主题；全部分块完成后跑一次全局合并，把跨块属于同一主题的候选并成一个主题，带多个时间段。合并是唯一看到整条视频的环节。
- **纠错先替换**（Q15）：每块转写完成后先按纠错词表做**字面替换**，替换结果才进入主题分析；生成笔记时把词表作为正确写法提示随请求传给模型。主题分析不传词表。
- **词表范围与优先级**（Q15）：词表是 JSON，一份全局 + 每视频一份；同一原文冲突时视频专属词条优先。

## Considered Options

- **逐块独立出笔记再拼接**：不需要全局合并，但同一主题被块边界切断时会裂成两节，笔记无法按主题跳转，因此不采用。
- **整篇字幕一次请求**：两小时视频的字幕远超一次可用请求的体积，端点上下文限制由用户配置决定、工具无法假设，因此不采用。
- **按任务分工的多端点**：用户要为转写后的两步分别配置端点，配置面变大且没有对应收益，因此不采用。

## 后果

- 端点是单点：配置错或服务不可用时，后两步整体失败；转写结果已落盘，改好设置后不必重转。
- 本 ADR 的端点由用户自备，不走 [ADR-0004](./0004-first-run-model-download-and-macos-first.md) 的模型下载器；首次启动下载的只有识别、说话人分离与标点模型。
- 块边界会切出半截主题：同一主题在相邻块各出一半候选，只能靠全局合并收拢；合并必须能处理同块多候选与跨块多对一。
- 字面替换不是模糊匹配：词条的大小写、空格、标点与原文不符就不会命中；也可能误改正常出现的同形字。这是已知代价。
- 候选主题很多时合并请求会变长，需要分批；分批会削弱“同一主题”判断的全局性，块数越多这个风险越大。
- 词表随生成笔记的请求一起发送，词表越大提示词预算越大；换端点或模型会让候选主题与笔记失效（见 [ADR-0006](./0006-hash-keyed-cache-and-topic-editing.md)）。
