# 已有主题的区间重跑只刷新字幕，不再重新分析主题

区间重跑（真实 ASR + 真实 LLM）会重新划一次主题：只要区间里还有新字幕，`analyzeVideoRange` 就调用 `segmentTopics` 并追加新主题记录。行级去重（ADR-0052、ADR-0058）压不住这一层——大模型对同一段内容总能划出「新」主题，而且多数与已有主题时间重叠 ≥75%。真机证据（HEAD `8105e2c`，v0.1.55，真实 LLM）：直播 ≈1841s 跑 4 个 10 分钟区间，主题 **7 → 13**；6 分钟访谈跑 6 个 1 分钟区间，主题 **3 → 9**。QA 实测新建主题里 6/7 与既有主题重叠 ≥75%，界面上就是一叠近似重复的主题卡。

## Status

已接受（accepted，2026-11-07，r93 / #150）。只改区间分析的**主题层**行为；字幕行去重（ADR-0052）、说话人对齐（ADR-0058）与 `video.json` 结构都不变。

## 决定

1. **门禁：区间整段落在已分析分块里，且视频已有主题。** `chunks` 的并集就是「已分析时段」（视频库导入写 ASR 分块，区间分析写本次区间，两者可能重叠，先合并再判断包含）。`topics` 为空时不走这条路，两个提前返回的复用分支（分块精确命中、重跑没有新字幕）同样要求 `topics` 非空：视频库导入先落 `chunks` 再划主题，主题分析失败会留下「有分块、没主题」的文档，那种区间必须照旧补一次主题分析。
2. **只重跑 ASR。** 转写、行级判重、说话人对齐、铸号、填充语过滤照旧；主题分析（`segmentTopics`）**不调用**，不写新 `TopicRecord`。重跑区间照旧记一笔 `chunks`：控制器按项目任务边界推进「已处理」时长，而重启后的 `slicedSecondsFrom` 只认分块——不记这一段，重启会让未切片时长退回上一个更大分块的起点。
3. **待确认主题（`proposed`）刷新建议行。** 返回区间内仍待确认的主题，`lineIds` 按当前字幕重新解析：新 ASR 补出来的行只要落在主题的时间范围里就自动进建议。主题的 id / 标题 / 时间段不变，确认弹窗读到的是最新的完整字幕。
4. **只有 `proposed`（待确认）主题会被重新提案；已确认 / 生成中 / 已切片 / 失败 / 需要重跑（`needs-rerun`）的主题原样不动。** 它们自己的记录（`queued` / `generating` / `done` / `failed` / `needs-rerun`，含切片字幕快照与切片文件）在 `video.json` 与项目清单里，重跑既不改写它们，也不把它们塞回待确认队列，避免同一个主题被切片两次。同一区间再次进来的复用分支（`chunks` 完全命中）用同一把过滤。
5. **落在任何主题时间范围之外的新字幕**只进完整字幕列表（确认弹窗仍可「补漏」勾选），不挂到任何主题，也不因此新建主题。
6. **从未分析过的区间**（不满足第 1 条）照旧跑主题分析并产生主题。

## Considered Options

- **区间新主题按时间重叠并入已有主题**（#145 QA 时提过的旧方案）：已由 Link 废弃——合并判据（重叠多少算同一个）本身就是又一层要用模型或阈值去猜的东西，且会改写已确认主题的时间段。
- **只靠行级去重压住新增字幕**：到 #145 收尾时同文同时重复已经 0 组、近似行也压到个位数，主题仍然翻倍——根因在主题层，压字幕治不了。
- **区间命中精确 `chunks` 才复用**（旧实现）：重跑范围与整段分析的边界很少完全一致（直播整段分成 780s 的 ASR 分块，重跑按 10 分钟切），几乎总走「重新划主题」那条路。
- **给 `chunks` 加「主题分析已完成」标记**：能区分「转写完成但主题分析没跑」与「分析完成」，但要动 schema；本轮用「视频已有主题」做替代判据，代价写在后果里。

## 后果

- 主题数量在重跑后不再膨胀：本票验证素材（`tmp/verify/r93-topic-refresh/`）直播 8 → 8（4 个 10 分钟区间）、访谈 2 → 2（6 个 1 分钟区间），全程 10 次区间分析的主题分析请求数为 0。上面引用的 7 → 13 / 3 → 9 是 #145 QA 在另一份主题状态上的对照数字。
- 重跑仍付出一次 ASR 成本（这是本票要的行为：字幕按新识别刷新）。
- **一个主题仍可能被多个分块的分析任务同时提案**，且暴露面比旧实现**更大**：旧实现只有「`chunks` 精确命中」与「重跑没有新字幕」两个复用分支会重新提案（还要求主题整段落在区间内、且不过滤状态），现在任何落在已分析时段内的重跑都会把与之相交的待确认主题重新返回。控制器以 `topicKey = jobId:topicId` 为键，同一底层主题被两个任务提案就有两条队列记录；自动切片开启时 `enqueueProposedTopics` 会各确认一次，项目清单可能多出一条重复 clip。本票不修：正确的去重键是主题 id 而不是 `topicKey`，属于队列展示层的另一张票（记录在 issue #150 的 proposed ticket 里）。
- 重跑会为自身区间记一笔 `chunks`：这让同一区间第二次重跑走「精确命中、直接复用」分支（不再跑 ASR），与既有行为一致；同时让重启后的「未切片内容时长」能按项目任务边界恢复。
- 「已有主题」是全局判据：视频库导入过（整段主题已划）的视频再加进项目，项目区间不再另建一套主题，只会刷新/提案既有主题；视频库转写完成但主题分析失败（`topics` 为空）的视频仍会正常分析。
- ADR-0058 结尾写的「主题数翻倍仍归 #150」由本 ADR 结清。
