# ADR-0048 Lab 行的文本归属：判重只认时间与说话人证据

issue #97（Link 2026-11-03 验收标注流程）：字幕行偶发被判成重复——听声音明明是两句不同的话，界面上两行却是同一段文本。

## Status

已接受（accepted，2026-11-03，r73）。

## 背景：根因证据

Lab 行组装的旧口径（`composeText`）是「文本行与 span 有一点时间交集就拼进去」：`min(span.end, row.end) - max(span.start, row.start) <= 0.02` 才跳过。抢话、以及超过 30s 的长段被 `splitSpan` 切开时，同一段解码文本会同时落在两行的时间范围里，于是被拼进两行——两行文本看起来重复，实际音频是两段不同的话。

一次性冒烟（`tmp/verify/r73-false-duplicates/`，夹具：主播 0–8s 话轮内嵌一个访客 2–5s 话轮，另有主播 9.5–14s 一段）：

| 行 | 修复前文本 | 修复后文本 |
|---|---|---|
| 0.0–8.0 speaker-1 | `主播讲国富论可以看到` | `主播讲国富论` |
| 2.0–5.0 speaker-2 | `主播讲国富论可以看到` | `可以看到` |
| 9.5–14.0 speaker-1 | `这讲的是分工` | `这讲的是分工` |

修复前两行文本完全相同（重复句），修复后各留各的。

## 决定

`apps/desktop/src/main/dev-lab/lines.ts` 用 `textOwners` 取代「有交集就拼」：**每段文本只归属一行**，判据只有两种证据，文字像不像完全不参与。

1. **时间证据**：取重叠秒数最多的那一行；重叠不超过 `OWNER_MARGIN`（0.02s）的行没有资格。只擦过边界的文本行不算这一行的内容。
2. **说话人证据**：重叠等长时（一段文本被两行完整覆盖，抢话处最常见）回它自己的说话人那行——`segtext` 行与分离段一一对应，段标签经 `assignSpeakers` 的映射换成 `speaker-1` 这类 id。说话人不可判（行数与段数不一致）时退到起点更贴近文本行的那一行。
3. **文字相似不构成重复**：两行文字相近甚至完全相同、但时间段不同（两次发言），两行都保留各自文本。判重不引入任何文本相似度阈值。
4. **真重复只留一份**：同一段文本同时落在两行的范围里时，只出现在有证据的那一行，另一行不再复制它。

空文本行仍然丢弃；说话人秒数/行数/样例起点照旧按可见行统计，口径不变。

## 备选方案

- **按文本相似度去重（编辑距离 / 公共子串）**：正是本单要排除的做法。本机 ASR 会把相邻话轮的上下文带进来，两句不同的话常常一大半字相同；按文字判重会删掉真实发言（`今天讲国富论` / `今天讲国富论的核心`），而真重复的两行文字也可能一字不差——文字不能区分这两种情况。
- **去掉重叠 span 的其中一行**：只有「谁插了谁的话」的时间证据才够判断（ADR-0046 的做法），本单不做归属调整，只决定文本进哪一行；两行音频都保留。
- **在 `splitSpan` 里避免把文本行切开**：切点由静音中点决定，文本行的边界来自分离段，两者不保证对齐；而且抢话重叠与切点无关，挡不住主要场景。
- **正式管线也同样去重**：正式管线按 span 解码音频、文本天然按行产生，不存在「同一段文本拼进两行」的问题；本单只修 Lab 的组装（ADR-0046 决策 2 的同一条边界）。

## 后果

- Lab 行视图不再出现「两行同一句话」；抢话处的文本回到各自的说话人，主播行不再带上访客那一句。
- 与 ADR-0046（r70 / #99）的归属规则同向且不重复：那单决定「哪些段不单独成行」，本单决定「一段文本进哪一行」。两处都改 `assembleLines` 时，以两边合并后的 `textOwners` 为准。
- 缺少说话人证据（导入的实验目录行数与段数不一致）时只剩时间证据，抢话等长重叠会退到「起点更贴近」的启发式——不引入文本判重，宁可两行各留各的。
