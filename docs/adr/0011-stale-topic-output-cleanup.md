# 重跑后清掉旧主题目录，manifest 用 topic.md 内容哈希记录所有权

对同一视频重跑 `vnote extract`，旧的主题目录与切片留在磁盘上。r6 实测：重跑后输出目录里留下 24 个主题目录，约 2.0 GB，而 `index.md` 只引用其中 8 个。旧目录里的 `topic.md` 与切片是过期产物，留着既占空间，也让按目录找笔记时出现两份内容不一致的笔记（ADR-0006 的后一条后果）。要清，必须先分清哪些目录是工具写的、哪些有用户自己的文件，避免误删。

## Status

已接受（accepted）。落实 [ADR-0006](./0006-hash-keyed-cache-and-topic-editing.md) 留下的清理策略，目录布局不变（[ADR-0002](./0002-filesystem-and-json-storage.md)、[ADR-0008](./0008-local-layout-corrections-file-and-cli-boundary.md)）。

## 决定

- **所有权记录**：视频输出目录里新增隐藏文件 `.vnote-manifest.json`，内容是一份按目录名排序去重的 `topicDirs` 数组，每项是 `{name, topicMdHash}`：`name` 是工具创建的主题目录名，`topicMdHash` 是当时写出的 `topic.md` 内容的 sha256。manifest 只记录所有权，不是产物索引；删掉后没有授权记录，只剩指纹清理。名字不是合法直属目录名（非空、不含 `/` 与 `\` 与 `\0`、不是 `.` 或 `..`）的条目直接忽略，不越出视频输出目录。
- **保留集**：一次运行成功后，只保留新 `index.md` 引用的主题目录；其余工具目录清掉。`index.md` 的引用集就是唯一真相，`--limit` 之类的局部运行也按它清理。
- **顺序**：先写完全部新主题目录与 `index.md`，再清理，最后写 manifest。`topic.md` 与 `index.md` 都先写同目录临时文件再 rename，中断不会留半截文件。旧 `index.md` 引用的 `topic.md` 可能已被同名主题的新内容替换。
- **幂等**：同一操作重复执行不再删除任何东西。
- **只删纯工具目录**：目录里每个条目都是普通文件（子目录、符号链接一律不通过），名字只能是 `topic.md`（必须存在）、`.DS_Store`、切片命名的 mp4，且至少一个切片 mp4；含任何其他文件、子目录或符号链接的目录保留。
- **内容哈希授权**：manifest 有条目的目录，只有 `topic.md` 内容与记录的哈希相符才授权删除；用户改过 `topic.md`（哈希不符）就保留。这样用户在 `topic.md` 里追加的批注不会被当纯工具产物删掉。
- **保留集大小写不敏感**：候选目录名与保留集名按小写比较。大小写不敏感的卷（macOS APFS 默认）上用户可能把 `foo` 改名为 `Foo` 而保留集里仍是 `foo`，大小写不敏感比较保证本轮刚写出的目录不会被当旧目录删掉。
- **哈希登记**：`keep` 里的目录登记本轮写出的 `topic.md` 哈希；只有保留下来但本轮没有写出的目录沿用记录的哈希。同名主题本轮重新生成且内容变了时新哈希生效，目录不会被永久误判为「用户改过」。
- **无授权记录**：历史目录与崩溃残留没有 manifest 条目，按上面的纯工具指纹清理。指纹是唯一误删边界：只有「没有 manifest 记录、含普通文件 `topic.md`、含至少一个切片命名的 mp4、且没有任何其他条目（子目录、符号链接、其他文件都不行）」的目录才可能被当工具产物误删；用户只放了 `topic.md` 而没有切片的目录不会被当工具产物删。
- **永不删**：`corrections.json`、`index.md`、`.cache`。
- **笔记缓存一起回收**：同时清掉本次没用到的 `<cacheDir>/note` 里的缓存文件；主题被删后它的笔记缓存没有复算价值。转写与主题候选缓存不动。
- **失败语义**：清理失败（manifest 损坏、写 manifest 失败等）只损失清理本身，`vnote extract` 仍成功并保留笔记，并会在 stderr 打一行警告（`清理旧主题失败: …`）提示用户。坏 manifest 不会自动修复：它留在磁盘上，本轮以及之后的每轮运行都跳过清理，直到该文件被修复或删除；删掉 `.vnote-manifest.json` 后下一轮按目录指纹重建授权。「下次运行再试」只适用于「目录删不掉」这一种情况：这类目录留在 manifest 里，下次运行重试。清理之后不重写 `index.md`。
- **只在完整运行末尾清**：清理只在整视频运行（`vnote extract`）末尾发生；将来按选定主题局部重生成时不得调用，否则会删掉本次没生成但仍被引用的主题目录。
- **已知限制**：同一视频并发跑两个进程会互删，工具假设一次只跑一个；「已建目录、切片没切完、还没写 `topic.md`」的崩溃残留不是纯工具目录，不会被清理。

## Considered Options

- **只信 manifest**：从第一次带 manifest 的运行起能列出全部工具目录，但升级前留下的历史残留不在任何 manifest 里，永远清不掉，因此不采用。
- **只信内容指纹**：不依赖 manifest，用户改过的目录一旦混入文件就不被识别，误判风险由用户承担；而且主题目录名可以复用，一个改过的旧目录会被误认为新目录，因此不采用。本设计只在无 manifest 条目的历史与残留目录上退回指纹，有记录的目录以哈希授权为准。
- **用 topic.md 内容哈希做授权**：manifest 名字加上 `topic.md` 内容的 sha256，删除前重新计算比对，能区分「工具写的原样 `topic.md`」与「用户改过的 `topic.md`」，又不用改文件布局，因此采用；代价是哈希只对 `topic.md` 生效，用户只放其他文件的保护靠纯工具判定兜底。
- **整目录原子交换**：把旧输出目录整个换掉最彻底，但目录 rename 在本地文件系统上不原子，中途崩溃会丢笔记，反而比原地清理危险，因此不采用。

## 后果

- 用户往主题目录里放了自己的文件，该目录会留下，并保留在 manifest 里，下次运行重新做清理判定；用户改过 `topic.md` 的目录同样留下（哈希不符不授权删除）。清理失败（manifest 损坏、写 manifest 失败）只损失清理本身，不中断运行，笔记已写好。
- 重跑后，`index.md` 未引用的纯工具产物主题目录会被清掉；留下的是以下例外：含用户文件的目录、用户改过 `topic.md` 的目录、因删不掉而留在磁盘上的目录。`index.md` 是唯一保留集的来源。
- manifest 删掉不致命：没有授权记录，退回纯工具指纹清理，下次运行重建。
- 历史目录与崩溃残留（无 manifest 条目）按纯工具指纹清；用户目录只有「无记录、含 `topic.md`、含至少一个切片命名的 mp4、且没有任何其他条目（子目录、符号链接、其他文件都不行）」时才可能被误删，只有 `topic.md` 没有切片的目录不会被删，这是本设计的已知边界。
- 原子写覆盖：`topic.md` 与 `index.md` 先写临时文件再 rename，中断不留半截文件；但旧 `index.md` 引用的 `topic.md` 可能已被同名主题的新内容替换，引用链接不保证内容不变。
- 清理在 `generateNotes` 成功后执行，耗时计入 `timings.cleanup`；笔记已写好，清理失败只留下残留，不影响本次产物。
